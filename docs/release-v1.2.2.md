# v1.2.2

> **歷史版本說明／舊平台架構。** 本文記錄的是 Discord-only 重構前的版本與測試；其中 QQ、AstrBot、OneBot、舊市集 commit 與舊安裝路徑不適用於目前分支。現行版本請看根目錄 README、`docs/install.md` 與 `docs/compatibility.md`。


从 v1.2.1 到这一版，做的是这些。两件事最大：**自由活动不再被权限闸拦住**，以及**外部核查提出的九处「零件好、接线不对」逐条修掉**。

## 自由活动不再被拦

「只浏览模式」整个删掉了。上一版是默认值改成可编辑、容器放行，闸还在；这一版把模式和判定一起拿掉：check() 恒放行，配置里写 browse_only 也不再改变行为。

代价写在明处：**花钱不再由代码拦**。「不乱花」从权限层挪回行为规矩（不打赏、不订阅、不买付费墙后的内容），这是她的选择，不是遗漏。

## 外部核查提的九处

| 项目 | 原来怎样 | 现在 |
|---|---|---|
| B站账号 | 恢复函数在作用域外引用 provider，一进去就报错、被吞掉：显示已登录，实际没换 | 内存/凭证服务/文件收成一个来源；恢复先校验再换；退出与迟到的扫码结果按代次判定；社交面不再自己读文件 |
| 工具分类 | 所有 bilibili_ 开头的工具一律算只读，「发评论」排不到禁止规则 | 分类按具体工具名，「发评论/改名/传头像」不再算读 |
| 扩展设置页 | manifest 声明了 options.html，仓库里没有（被 .gitignore 的 *.html 挡住） | 补进仓库并加精确例外；新增检查验「manifest 引用的文件都在」 |
| 群里回执身份 | 入站带 bot/会话，回执只带 eventId，同一条消息被算成两条 | 三处写同一份身份；只有 eventId 的老回执照样在唯一可关联时回接，判不出就记 orphan，不猜 |
| 兴趣回复 | 模型只吐思考过程时，那段文字会被当成回复写进待发箱 | 只认正式答案通道；没有答案就如实说没有 |
| 兴趣转发 | 20 秒定时器不管上一轮，同一行会调两次模型、写两个箱子；已处理超过 800 条后旧请求会重放 | 不重入；记账改成「游标 + id 集合」；箱子用稳定 jobId |
| 网页取文（旧口） | 新的 /pick 要 token，旧的 47322 口同时在跑且不配对 | 旧口默认不启动，onWebPick 默认关（要接老扩展得显式开） |
| 网页取文（状态） | 待处理只在内存，重启就忘；自动答完也不结账 | 状态落盘可恢复；「明确答了」才结账，失败留原因可重试；消费按 id 校验 |
| 索引读取 | 快照拍了，但查询还是读 live 里的散文件 | 查询认 rag-index/current.json，从不可变代目录一次读齐四个文件；代不完整或比 live 旧就退回 live |

顺带两处小修：注入对照里「账本缺字段」不再显示成 0，改成「无数据」；账本与组装并列显示时标明「未关联」。

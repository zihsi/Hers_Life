> **歷史版本說明／舊 QQ + AstrBot 混合架構。** 本文記錄的是 Discord-only 重構前的 release 行為；其中的 AstrBot、QQ、OneBot、舊路徑與設定不適用於目前分支。現行功能與安裝方式請看根目錄 README、`docs/install.md` 與 `docs/capability-table.md`。

从 v1.1.1 到这一版，做的是这些。

## 新增

**网页取文并进了桌宠的浏览器扩展**

以前是单独的接收端，另装一个扩展。现在用桌宠自带的那个：选中一段文字右键「交给溟：看这段」，或右键「溟：指一段」让光标指认整块。带配对 token、每条带请求 id、上一段没取走时拒收（不覆盖）。真机验过两次。

**群里「本来不回、但撞到兴趣话题」的那一种话，改由 DSH 生成**

以前这种也是 AstrBot 自己想说就说。现在是：AstrBot 只负责判断「该不该接」，真正说什么交给 DSH —— 因为 AstrBot 那边没有 DSH 的上下文（人设、记忆、索引、群里刚聊过什么），它生成的话不像本人。

**普通回复不受影响**，仍然一道，AstrBot 自己生成直接发。

代价：这条链路是文件当队列、20 秒一轮，从命到发出最长约 40 秒。

**B站 登录不用重启了**

账号状态统一成一个模块，扫码登录后立刻生效，不用重启 DSH。另外退出登录会留一条记号，防止旧凭证把人「复活」回来。

**索引能断点续跑**

以前嵌入跑到一半断了，这一轮的向量全丢、重跑从零开始。现在每批算完就落盘（`live/doc-emb-checkpoint.{json,f32}`），下次按 hash 认领。实测中断在 64/300 块，重启后复用 182/300，33 秒跑完。

顺带：索引有了 manifest（维度/模型/条数/路径可校验），发布改成原子写，维度或条数不符就拒绝发布、永不删当前代。

**注入量对照**

`node scripts/inject-report.mjs` 把「组装了多少字 / 请求实际多少 token / 命中多少缓存」三档分开显示。以前只有一个笼统的「注入总账」，看不出差在哪。

## 改了

- **权限边界**：只浏览的约束现在只管「没有 DSH 远端调用权」的主体，本人和两个自己人放行；花钱类操作仍然拒绝。名单按 `- _ : .` 切段整段相等匹配，不做子串猜。
- **入站记录**：每条带平台消息 id（不再用正文哈希认身份），带处理状态三态（未定 / 不接 / 要回了）。

## 两个工具，推送和上线前用

```bash
node scripts/check.mjs --suite offline    # 25 项离线检查
node scripts/check-privacy.mjs            # 有没有真实号/凭证混进仓库
```

## 已知限制

- **发送后回执拿不到**：AstrBot 的「发送后钩子」按「参与过这条消息的插件」过滤，纯旁观的记录插件收不到。所以只做到「要发了」这一步，`handled` 留空，不伪造。
- **兴趣链路延迟约 40 秒**（文件队列 + 20 秒轮询）。
- **索引评测用的是合成语料**，缺真实题库。
- 深水区群在 DSH 里没有会话，兴趣投递暂时到不了那里。

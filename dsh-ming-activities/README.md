# 共同活动卡（可选插件）

记录一起读的书、看的视频、玩的游戏或做的小项目：标题、来源链接、当前进度、下次接着做什么，以及进行中/暂停/已完成/不再继续。

**由人手动创建和修改。** 不抓取聊天、不自动建记忆、不注入每轮提示、不定时催促、不调用模型，不判断感情。它与现有核心记忆政策分开，既不扩大长期记忆写入范围，也不改群聊和私聊共享方式。

## 安装和使用

这是新插件，不会因为拉取分支就自动开启。沿用仓库的 `link:` 安装方式：

1. 在实际使用的 DSH profile 的 `package.json` 中增加依赖 `"dsh-ming-activities": "link:<源码目录>/dsh-ming-activities"`，把 `<源码目录>` 换成检出的真实目录；保留原有依赖。
2. 把 `"dsh-ming-activities"` 加到同一 profile 的 `dsh.profile.bundles` 数组，保留原条目。使用 DSH 原有方式刷新该 profile 的依赖。
3. 工作區由 Hers Life 設定中心統一提供；獨立使用時也可在 `ming-activities` 插件配置 `root`。沒有配置時會提示，不會隨便選一個目錄保存。
4. 重启 DSH 并刷新网页，设置里打开 **共同活动**。需要宿主网页的 slots 和 webServer 服务；纯命令行环境没有此页面。

填写标题和进度后点“保存活动”。链接可留空；填写时仅接受 http/https。用“编辑”修改进度或状态，用状态筛选查找暂停或已完成的活动。

“复制接续说明”只复制到剪贴板，需要时自己贴入聊天。**AI 不会自动知道你改了卡片**；这版刻意不在每轮增加上下文或开启处理。删除需再点一次“确认删除”，只删除活动卡，不删链接里的作品、记忆或聊天。

## 数据、退出与限制

记录在 `<工作区>/live/shared-activities.json`：版本、列表 revision，以及每条的 id/title/url/progress/next/status/created/updated。它是独立手动进度表，不是新的核心记忆库。`created` / `updated` 按 ISO 时间保存，页面显示为浏览器本地时间。

查看不会创建文件；首次保存才建立目录和文件。保存使用临时文件替换，同一插件实例按序写入。两个页面读了同一版本时，先保存的成功，后保存的收到冲突提示且保留草稿，刷新并核对后再保存。**同一资料文件只由一个 DSH 实例负责写入**，不提供多进程或多人实时协作锁。

损坏或不认识的文件格式会报错并保留原文件，不会重置为空。重要活动可随工作区一起备份；删除卡片没有回收站。停用时从 profile 的 bundles 中移除本插件并重启，记录文件仍保留，可保留以后恢复使用；移除源码也不会自动删除资料。

不迁移、不覆盖现有 reading/watch/日记文件，不自动抓视频时间或监视窗口，不产生后台模型费用，不为用户做画像。

## 复查与验收

```
node dsh-ming-activities/qa-activities.mjs
node --check dsh-ming-activities/index.js
node --check dsh-ming-activities/store.js
node --check dsh-ming-activities/client.js
```

合成数据覆盖空目录、创建、重新加载、各状态、编辑、删除、并发冲突、非法内容、损坏文件保留和 HTTP 接口约束。本地 Node 26.7.0、React 18 + Edge 还实测了创建、编辑、暂停、刷新后保留、剪贴板、双页面冲突保留草稿、状态筛选、删除确认及 390 像素窄屏布局；无页面异常。真实 DSH 的 profile 加载、网页挂载与朋友的目录权限仍需实机确认。

朋友试用时先添加一张不涉及隐私的测试卡，刷新网页确认仍在，再改成暂停、复制接续说明、最后删除。确认好用后再录真实活动。
